# Spark DNS Resolution Error on Kubernetes

## Error Description

When running the `batch_pipeline` DAG in Airflow, specifically the `silver` task (which uses `SparkSubmitOperator` in `client` mode), the Spark job fails to acquire resources and eventually times out. The Airflow logs show the following warning repeatedly:

```text
WARN TaskSchedulerImpl: Initial job has not accepted any resources; check your cluster UI to ensure that workers are registered and have sufficient resources
```

## Root Cause

The core issue is a **DNS Resolution Failure** (`UnknownHostException`) between the Spark Worker pods and the Spark Driver running inside the Airflow Scheduler pod.

1. **Client Mode:** The Spark Driver runs within the `airflow-scheduler` pod.
2. **Hostname Registration:** The Driver registers itself with the Spark Master using its pod's autogenerated hostname (e.g., `airflow-scheduler-587dcbb578-rrx5r`).
3. **Connection Failure:** When the Spark Master allocates executors on the `spark-worker` pods, these executors attempt to connect back to the Driver using that hostname.
4. **UnknownHostException:** In the default Kubernetes networking setup, pods cannot resolve the dynamically generated hostnames of other pods unless governed by a Headless Service. Consequently, the executors crash immediately upon startup with:
   ```text
   Caused by: java.io.IOException: Failed to connect to airflow-scheduler-587dcbb578-rrx5r:44281
   ...
   Caused by: java.net.UnknownHostException: airflow-scheduler-587dcbb578-rrx5r
   ```
5. **Resource Starvation:** Because the executors continually crash and restart, the Driver never receives any active executors to process tasks, leading to the "Initial job has not accepted any resources" warning.

## Recommended Solution

The most robust and least invasive solution is to force the Spark Driver to announce itself using the pod's IP address instead of its hostname.

1.  Use the Kubernetes Downward API to inject the `POD_IP` into the `airflow-scheduler` container as an environment variable.
2.  Update the `SparkSubmitOperator` configuration in the Airflow DAG to set `spark.driver.host` to this `POD_IP`.
